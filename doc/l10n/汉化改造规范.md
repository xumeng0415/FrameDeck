# FrameDeck 中文汉化改造规范与风险点位清单

- 版本：v1.1（已对齐 `doc/l10n/术语表.md` v1.0）
- 适用代码库：`FrameDeck-main`（Python 3 + PySide6，28,077 行）
- 目标：把所有**面向用户的英文文案**改为简体中文，术语对齐 DaVinci Resolve / Nuke Studio 中文版口径
- 硬约束：**零功能行为变化、零重构、零新增依赖**（不引入 gettext / QTranslator / `.ts` / `.qm`）
- **两份文档的分工（读之前先记住）**：
  - `doc/l10n/术语表.md`（产品出品）= **每个词译成什么**，唯一译名依据；
  - 本文档（架构出品）= **哪些字符串能译、怎么改不会坏、先改哪批、怎么验**。
  - 两者冲突时：**本文档的「禁止翻译表」优先**（那是代码约束，不是文字偏好）；文字层面的冲突（如全角/半角标点）见 §0.2 的两条已裁决项。

## 0. 结论摘要（先看这里）

汉化的真实风险**不在"翻译"，而在"显示文本同时被当作程序标识符"**。全库共发现 **6 处显示文本被用作逻辑匹配**、**3 处显示文本被持久化到 QSettings/JSON**、**9 个测试断言直接比对英文 UI 文案**，另有 **1 处固定宽度标签 + 1 处字符串分隔符依赖** 会因中文宽度/全角符号而失效。

一句话原则：

> **凡是"能反查回来"的字符串，一律不许动；只有"只写不读"的字符串才可以翻译。**

三条判据（施工时逐条对照）：

1. 该字符串是否被 `==` / `!=` / `in` / `dict(...)` / `.index()` / `findText()` 反查？→ 是则**禁止翻译**，或"翻译 + 同步改匹配字面量"。
2. 该字符串是否被写入 QSettings / JSON / CSV / `.fdplaylist` / shot sidecar？→ 是则**禁止翻译**。
3. 该字符串是否被 `split()` / 正则 / 宽度计算依赖？→ 是则**翻译时必须保住分隔符与占位符**。

### 0.1 术语表 §3.2「字面量锁」L-01～L-06 —— 本文档全量引用，优先级最高

## 1. 改造原则

| # | 原则 | 说明 |
|---|------|------|
| P1 | 只改字面量 | 只替换「引号内的展示型字符串」。函数签名、默认参数名、变量名、控制流、数据结构形状一律不动 |
| P2 | 不改结构 | 不合并/拆分函数，不把字面量抽成常量表，不改 `self.values` 的语义（除非 §3.3 的 `label` 方案） |
| P3 | 不加依赖 | 不引入 gettext / `QTranslator` / `tr()` / `.ts` / `.qm` / babel；不新增文件 |
| P4 | 只改一层 | 显示层与数据层分离的组件（如 `(key, label)` 元组、`{"code","value"}` 字典），**只动显示字段，绝不动 key/value** |
| P5 | 占位符不变 | `%s %d {0} {name} :04d` 的数量、顺序、类型、首尾空格、前后缀符号全部保留 |
| P6 | 单位与缩写保留 | `FPS / ms / GB / % / x / A / B / RGB / EXR / DPX / OCIO / ACES / AOV / ID / HDR` 不译 |
| P7 | 软件名不动 | `FrameDeck`、`framedeck`、`0.0.1-beta.12`、`Motion-Craft` 全部原样 |
| P8 | 失败即回滚 | 每批一份可回滚基线（见 §6.0）；**L1 `compileall` + L2 `check_l10n.py --strict` 未双绿则回滚该批**，不带病往下做（本机无 PySide6，pytest 不可用，见 §7.0） |

### 2.2b 术语表「已定稿验收项」V-01 ~ V-03 的代码落点（工程硬约束）

> 术语表 §3.1 定稿了 4 条验收项。下表把它们映射到具体代码位置，并**更正了术语表里的 2 处事实性笔误**（`_COLUMNS`/`pos` 在代码里不存在）。

| 验收项 | 要求 | 代码事实（已核实） | 施工动作 |
|---|---|---|---|
| **V-01** 持久化字段名不进翻译表 | CSV 表头、`.fdplaylist` 键、笔记 sidecar JSON 键一律不动 | `utils/notescsv.py:27` 常量名是 **`COLUMNS`**（无下划线前缀），9 个键依次为 `frame, timecode, type, content, color, x, y, done, timestamp`（注意是 **x / y** 两个键，不是 `pos`）；`:161` `csv.DictWriter(fieldnames=COLUMNS)`；值层面 `done` 写 `"yes"/"no"` | **禁译**。抽取脚本要从 `COLUMNS` 这类常量上**显式排除**：只收"准备显示给用户的字符串"，不要"收所有字符串字面量"。⚠️ 若按术语表的 `_COLUMNS`/`pos` 去 grep 会搜不到，误判成"没有这个常量" |

### 2.3 “同一字面量两种角色”专项规则（最容易踩雷）

有些英文串**既是显示文本、又是分支条件**。处理方式只有两条：

- **R-a 同步改写**：把显示与匹配两处改成**同一个新中文串**（等价替换，逻辑零变化）。适用于 6 处（见 §3.1）。
- **R-b 拆分显示字段**：给数据加 `"label"` 只用于显示，`key/value` 保持不变。适用于 `REVIEW_TYPES`。

**绝不做**：把比较字面量改成中文、却漏掉显示处（或反之）；也不要把比较改成 `startswith` / `in` 之类的"容错匹配"（那是逻辑改动）。

### 3.3 `REVIEW_TYPES` 最终方案（最小侵入，推荐实施）

**结论：`value` 一个字符都不许动；新增 `label` 作显示字段，并让 `ContextCombobox` 优先读 `label`。**

现状核实：

- `ReviewTypeCombobox`（`comboboxs.py:461-467`）`key="value"`
- 显示值来自 `ContextCombobox.setItems`：`self.values = [x[self.key] for x in self.contextList]`（`comboboxs.py:132`）
- 消费方只有 `recaps.py:589 self.reviewTypeCombobox.setValue(0)`（**按下标**）与 `recaps.py:700 getValue()`（**返回 dict**）
- 全库**没有任何** `ReviewTypeCombobox.setValue("字符串")` 的调用 → 显示串不参与回填
- 但 `getValue()["value"]` 会进入 `scripts.Review.set()` → `sg_review_type`

改动（2 处，共 2 行 + 6 行数据）：

```python
# widgets/comboboxs.py:132（setItems 内，唯一改动）
self.values = [x.get("label") or x[self.key] for x in self.contextList]
```

```python
# constants/__init__.py:232-263（只加 label，value 原样）
{"value": "Comment", "label": "评论", "tooltip": "...", "color": "#81c784"},
{"value": "Correction", "label": "修正", ...},
{"value": "Clarification", "label": "澄清", ...},
{"value": "Retraction", "label": "撤回", ...},
{"value": "Reaction", "label": "反馈", ...},
{"value": "Approved", "label": "已通过", ...},
```

为什么安全（逐条证明）：

1. `self.values` 与 `self.contextList` **等长同序** → `setValue(int)` 下标、`setValue(dict)` 的 `.index()` 全部不变；
2. `findByKey(value, key)` 仍按 `key`（=`"value"`）匹配内部值 → 不变；
3. `setValue("字符串")` 在 ReviewType 上**无调用**；若将来有人传内部值 `"Comment"`，会落到 `index=0`（`comboboxs.py:178` 的既有兜底），与今天的行数一致；
4. 其它 3 个用 `ContextCombobox` 的类**没有 `label` 键** → `x.get("label")` 为 `None` → 回退到原 `self.key`，行为 **0 变化**：
   - `StatusTypeCombobox`（`STATUS_LIST` 无 label）
   - `FbsCombobox`（`FPS_VALUES` 无 label）
   - `ProjectCombobox`（`scripts.Projects.get()` 返回的 dict 无 label —— **施工时禁止给 projects.json 加 label**）
5. **（长期约束，产品复核后新增）** 加了 `label` 兜底之后，`self.values` 已经是**中文标签**，而 `setValue(字符串)` 走的是 `self.values.index(value)`（`comboboxs.py:178`）。任何"按英文串设置"的调用都会 **静默落到索引 0**，不报错。因此定一条硬规则：

   > **凡用 `ContextCombobox` 的枚举下拉，只允许按"索引（int）"或"context dict"设置，禁止按显示串设置。**

   现状核查：全库唯一的 `ReviewTypeCombobox.setValue` 调用是 `recaps.py:589 setValue(0)`（索引）；`StatusTypeCombobox` 走 **`recaps.py:590`** `setValue(status_display)`（注意是 **590**，与 589 相邻但不是同一行），而 `status` 来自 `utils.getStatusFieldValue()`（同源于 `STATUS_LIST.code`），**译后两边同源仍命中**。这两条是安全的前提，**后续新代码不要破坏它**。
6. **`REVIEW_TYPES[*]["tooltip"]` 裁定：不译。** 依据（工程师 grep 核实）：全库 `["tooltip"]` / `get("tooltip"` 的读取点只有 `buttons.py` / `comboboxs.py` / `lineedits.py` 的 `kwargs["tooltip"]`，**没有任何代码读 `REVIEW_TYPES` 里这 6 条** → 只写不读的死字符串。因此：

   - B1 的 `constants/__init__.py` 计数 **28 条 = LOOP 3 + COMPARE 9 + STATUS code 10 + REVIEW label 6**，**不含 tooltip**，与批次表一致；
   - 顺带记录两处原文瑕疵（**不修**，改了也不显示）：`"Comment? Notifiction message to artisan"` 拼写错（Notification）；Retraction 那条前缀写成 `"Correction? taking back something you previously said"`，前缀词标错。
   - 铁律重申：**死字符串不因为"反正不显示"就去改** —— 每一处多余改动都是回滚面积。

**备选方案（若不想动 `comboboxs.py`）**：直接不译 `REVIEW_TYPES`（保持英文 `Comment/Correction/...`）。代价是评审类型下拉框留英文，但零风险。**不推荐"直接翻译 value"**：会同时污染落盘数据、预设数据与 ShotGrid 回传字段，且历史 note 无法回溯匹配。

### 4.2b HUD 绘制层映射规格（裁决 1 / M3 —— 全项目唯一允许新增的代码）

`playback/stats.py` **一行不改**。中文只出现在 `widgets/viewer.py::_draw_stats_hud`（`1908-1965`）内部。

**先说清一个容易搞错的事实**：`hud_lines()` 返回的是 `(label, value, ok)` 三元组，其中

- **6 个标签**（不是 7 个）：`FPS` / `FRAME` / `RES` / `DECODE` / `CACHE` / `DROPPED`
- `STALLED` **是取值，不是标签** —— 卡顿时 `stats.py:177` 产出的是 `("FPS", "STALLED", False)`，即"FPS 这一行的值是 STALLED"。所以映射分两类：**6 个标签 + 2 条取值规则**（`STALLED`、`"N frames"`）。

| 类型 | 原文 | 中文 | 依据 |
|---|---|---|---|
| 标签 | `FPS` | 帧率 | F-18 |
| 标签 | `FRAME` | 帧 | F-18 |
| 标签 | `RES` | 分辨率 | F-17 |
| 标签 | `DECODE` | 解码 | F-06 |
| 标签 | `CACHE` | 缓存 | F-01 |
| 标签 | `DROPPED` | 丢帧 | F-09（V-03：全项目仅此一处"丢帧"） |
| 取值 | `STALLED` | 卡顿 | F-16 |
| 取值 | `"{n} frames"` | `"{n} 帧"` | F-18 量词 |

**不改**：`{ms} ms`（`ms` 是单位，保留）、`"{measured:.1f} / {target:g}"`、`"{w} x {h}   {proxy}"`（3 空格是对齐，L-04 同类）、`"--"`、`{n}` 计数。

**实现（约 10 行，全部在 `viewer.py` 内，不动 `stats.py` / 不动 `__init__.py:2490` 的调用方）**：

```python
# widgets/viewer.py —— 模块级常量（放在类外或类属性均可）
HUD_LABELS = {
    "FPS": "帧率",
    "FRAME": "帧",
    "RES": "分辨率",
    "DECODE": "解码",
    "CACHE": "缓存",
    "DROPPED": "丢帧",
}


def localized_hud_rows(rows):
    """Return a display-only copy of the HUD rows with Chinese labels.

    The English rows stay the contract of playback.stats.hud_lines(); this
    function only prepares text for drawing, so tests and any future consumer
    of hud_lines() keep working on the original keys.
    """
    localized = list()
    for label, value, ok in rows:
        if value == "STALLED":
            value = "卡顿"
        elif value.endswith(" frames"):
            value = value[: -len(" frames")] + " 帧"
        localized.append((HUD_LABELS.get(label, label), value, ok))
    return localized
```

然后在 `_draw_stats_hud` 里把**唯一一行**改掉（`1910`）：

```python
# 改前
rows = self.stats_rows
# 改后
rows = localized_hud_rows(self.stats_rows)
```

**四条硬约束（违反任意一条即视为改坏）**：

1. **不许改 `set_stats_rows`** —— `self.stats_rows` 必须继续存英文元组（`viewer.py:1902-1906`）。
2. **不许改调用方** —— `widgets/__init__.py:2490-2500` 的 `statsmath.hud_lines(...)` → `set_stats_rows(rows)` 原样保留。
3. **不许改 `hud_lines()` / `PlaybackStats`** —— `tests/test_stats.py` 的 12 处 `rows["FPS"]` 断言是"stats.py 没被动"的守门测试，必须保持全绿。
4. **宽度必须用映射后的行来量** —— `label_width` / `value_width` 现在是 `max(metrics.horizontalAdvance(row[i]) for row in rows)`（`1914-1915`），只要 `rows` 已换成中文副本，浮层会自动适应中文宽度；**不要**手工加 padding 或 setMinimumWidth。

**已知视觉风险**：HUD 用的是 `QFont("Consolas")`（`1916`），无中文字形 → Qt 逐字回退到系统中文字体，行高与字宽会变。因为浮层尺寸是动态量出来的，**不会截断**，但需要人工目检一次（B5 判据已列）。若目检发现中文比英文明显偏高、与边框贴住，**唯一允许的调整**是把 `:1916` 的字号 9 → 8（属样式微调，不改结构），并在 commit message 里注明。

## 7. 验证方案（本机无 PySide6 → 门禁降级，如实声明）

### 7.0 门禁结论（降级版，必须先读）

**环境事实（team-lead 与产品各自实测，结论一致）**：本机 `pip install PySide6==6.9.0 pytest numpy` 失败（PySide6 主包 66 MB，`IncompleteRead`），此后：

```
python -c "import PySide6"   → ModuleNotFoundError: No module named 'PySide6'
python -m pytest             → No module named pytest
```

**`pytest` 本身也没装** —— 不是"PDF 那 4 条断言验不了"，而是**全项目所有测试都验不了**。因此本机**不存在任何"某测试已通过"的事实**，报告里也不得出现此类表述（见下方表述禁令）。

**因此原定的 `QT_QPA_PLATFORM=offscreen pytest` 无法执行，门禁降级为"静态等价"**。注意：**不能假装跑过**——最终交付说明里必须写明「**未经 GUI 实机验证**」。

| 层 | 内容 | 命令 | 能抓 | 抓不住 | 本机可执行 |
|---|---|---|---|---|---|
| **L1** | 语法/编码 | `python -m compileall -q …` | 括号/引号/缩进/编码错误、误删代码块 | 占位符错位、`==` 匹配失效、运行时 `NameError` | ✅ |
| **L2** | 静态等价检查 | `python doc/l10n/check_l10n.py --baseline d3d8497` | 残留英文、占位符漂移、越界改动、断言漏改（A 类） | 布局截断、字形缺失、绘制层映射的视觉正确性 | ✅ |
| **L3** | 真机/离屏视觉 | `pytest` / GUI 冒烟 | 渲染、字体、点击链路 | — | ❌ **不可执行** |
| **L4** | 人工目检 | 人眼 | 豆腐块、挤压、HUD 串位 | — | ⚠️ 受限（需有 PySide6 的机器） |

**判定**：L1 + L2 两绿 **不足以**宣布"汉化完成"，只能宣布"源码级完成，未经 GUI 验证"。谁在有 PySide6 的机器上补跑 L3，谁负责在报告里追加结论。

**表述禁令（硬性，任何人都适用）**：

| 禁止写 | 只能写 |
|---|---|
| "测试已通过" / "pytest 全绿" / "xx 用例已验证" | "该用例**未执行**（本机无 pytest）" |
| "静态检查全绿，可以验收" | "静态检查通过（L1+L2）；**未做 GUI 实机验证**" |
| "PDF 中文正常" | "PDF 中文**未目视确认**" |

理由：`check_l10n.py` 只能证明"字面量没改错、占位符没丢、没越界"，**证明不了界面显示正常**。把两层混为一谈，就是最容易漏掉的交付缺陷。

### 7.2a 白名单机制（避免"合规英文"被误报）

`check_l10n.py` 内有两张表，职责不同：

| 表 | 内容 | 作用 |
|---|---|---|
| `WHITELIST` | 形如 `(文件子串, 精确子串, 理由, 何时该删)`，只列**能出现在 UI 调用参数里**的合规英文（当前仅 1 条：`ocio.py` 的 `ACES 1.2 Legacy`） | 命中即归 `ALLOWED`，不判失败；带第四列的条目为施工中间态，到期必须删（脚本会提示） |
| `EXEMPT_NOT_SCANNED` | 刻意保留英文、但**不是 UI 调用参数**的字符串（字体族名 `Segoe UI`/`Helvetica`/`Consolas`、`"Radius"` 这类 `setValue` 实参、`FPS_VALUES[*]["code"]`、`REVIEW_TYPES[*]["tooltip"]`…） | 扫描器本就看不到它们；保留此表只为"为什么这些英文没被报"有据可查（`-v` 时打印） |

**这套分法解决了"淹没有效信号"的问题**：`WHITELIST` 越短越可信（1 条），大量"刻意英文"根本不进扫描面，所以不需要靠白名单去放过 —— 也避免了"`FrameDeck` 一词进白名单 → 顺手放过 `FrameDeck Codec Support`"这类**白名单腐化**（初版就踩过，已删）。

**白名单原则**（脚本内 `ALLOW_EXACT` / `ALLOW_PREFIX` / `WHITELIST`）：只放**缩写、品牌、格式串、库契约、禁译代码值**（`FPS/GB/ms/RGB/EXR/OCIO/ACES/Space/Ctrl/Ok/Yes/Question/Auto`…）。**不许**为了让检查变绿而把某个待译词塞进白名单——那是自己骗自己。
反例（真实踩过）：初版把 `FrameDeck` 一词放进白名单，结果 `"FrameDeck Codec Support"`、`"Save FrameDeck Playlist"`、`"Clear FrameDeck Cache"` 全被当成"合规英文"放过 —— 而这三条**必须译成**「FrameDeck 编解码器支持 / 保存 FrameDeck 播放列表 / 清除 FrameDeck 缓存」。品牌名本身由 `ALLOW_EXACT` 精确匹配（仅当整条字面量就是 `FrameDeck` 时放行），不做子串放过。

**已知的两类误报**（看输出时自行过滤，不要改代码去迎合脚本）：

1. 经 `self.` 调用的 Qt 静态方法（`self.information(...)`）会被 `NON_UI_ROOTS` 跳过，若某处漏网属脚本局限；
2. `notescsv` 之类的数据模块里出现的多词英文（如 CSV 列名）会进 residue —— 它们是 V-01 禁译项，**判定为"允许存在但需在报告注明"**，不进白名单（因为目标状态是"扫描器不该把它们当 UI 文案"，而不是"放过它们"）。
