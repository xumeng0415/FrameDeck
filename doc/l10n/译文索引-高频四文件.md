# 译文索引（高频四文件 · 原文精确子串 → 译文）

配套文档：`doc/l10n/术语表.md`（术语与规则，权威）。本文件只解决一件事：**工程师不需要先读术语表，直接搜原文、贴译文。**

## 使用方法

1. 打开目标文件，`Ctrl+F` 搜「原文」列的**精确子串**（含空格、含省略号、含代码里的拼写错误）。
2. 贴「译文」列的内容。译文中若含 `{...}`，**整段照抄**，不要改占位符。
3. 行号列只作参考——每改一行，后面的行号全部会漂移，**不要用行号定位**。
4. 「原文」列为 `f"..."` 的，说明原文是 f-string（或跨行拼接），译文同样是 f-string 形态；这类改动风险最高，改完必须实际跑一次该界面。
5. 本表未覆盖的字符串：先查术语表；术语表也没有 → 报给 team-lead 转产品裁决，**不要自行造句**。

覆盖范围：`widgets/__init__.py`、`widgets/viewer.py`、`widgets/playlist.py`、`widgets/pdfreport.py`，共 **185 条**（另含一整块多行快捷键说明，按整块替换，不计入条目数）。

### 红线 2：`utils/timecode.py` 整体不译，`_TIMECODE_RE` 禁改

- 该文件**一行不改**：4 条 drop-frame 异常文案（`:67`、`:124`、`:126`、`:133`）保持英文——它们无界面调用方，译了属无效改动。
- 更要紧的是 `:15` 的正则：

```python
_TIMECODE_RE = re.compile(
    r"^(?P<sign>-?)(?P<hours>\d+):(?P<minutes>\d{2}):"
    r"(?P<seconds>\d{2})(?P<separator>[:;])(?P<frames>\d{2})$"
)
```

  `(?P<separator>[:;])` 里的**半角分号是区分 drop-frame 与 non-drop 的唯一标记**。
- **全角标点规则的边界**：中文文案句子里的分号写成全角 `；`；但凡**同一行存在代码语义**（正则字符集、字符串比较、CSV 分隔、键名）的分号与冒号，**绝不碰**。
- 自查：`grep -n "\[:\;\]" utils/timecode.py` 仍返回 `:16` 原样；文件 `git diff` 为空。

### 红线 3：`utils/notescsv.py` 的 `COLUMNS` 表头禁译

- 常量名 `COLUMNS`（无下划线前缀，`:27`），9 个键 `frame, timecode, type, content, color, x, y, done, timestamp`——**注意是 `x` 与 `y` 两个键，没有 `pos`**。

## 0.1 验证状态与结论边界（验收前必读）

本机实测：**`PySide6` 未安装、`pytest` 亦未安装**（`import PySide6` → `ModuleNotFoundError`；`python -m pytest` → `No module named pytest`）。因此本次汉化**没有任何运行时或测试层面的验证**。

| **实际渲染效果**（文案宽度、是否被截断、状态条是否仍对齐、下拉是否撑破 86 px） | ❌ **不可验** | 必须有人工在装有 PySide6 的机器上目视 |
