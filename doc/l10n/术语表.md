# FrameDeck 中文汉化术语表（权威版）

- 适用版本：FrameDeck v0.0.1-beta.12（Python 3 + PySide6）
- 文档性质：**本次汉化的唯一翻译依据**。工程师改文案时以此表为准；表里没有的词，先查第 5 节风格规则，仍无法确定须回到产品确认，不得自行造句。
- 术语来源：逐文件核对真实 UI 字符串（`widgets/__init__.py`、`widgets/viewer.py`、`widgets/playlist.py`、`widgets/shotstrip.py`、`widgets/comments.py`、`widgets/ocio.py`、`widgets/imageexport.py`、`widgets/videoexport.py`、`widgets/cachemanager.py`、`widgets/pdfreport.py`、`widgets/recaps.py`、`constants/__init__.py`、`playback/proxy.py`、`playback/stats.py`、`utils/notescsv.py`、`README.md`），不是凭空对照词典。
- 中文标尺优先级：**DaVinci Resolve 中文版 ＞ Adobe Premiere Pro / After Effects 中文版 ＞ Nuke / RV 中文资料 ＞ 3ds Max / Maya 中文版 ＞ 中文影视视效行业惯例**。
- 每个词条只给**一个**中文译名。凡中文软件里存在多种叫法的，本文已做裁决并写明理由，不向工程师暴露并列选项。
- **配套施工文件**：`doc/l10n/译文索引-高频四文件.md`（184 条「原文精确子串 → 译文」，覆盖 `widgets/__init__.py`、`viewer.py`、`playlist.py`、`pdfreport.py`）。工程师按"搜原文→贴译文"施工，不必先通读本表；本表用于判定本文件未覆盖的字符串。

### 1.1 命名冲突规则（通用，优先于任何单词条的既有写法）

这一节解决的是"两个词条各自都对、放在同一界面上会撞"的问题。撞词不是工程师抄错，是表自身的缺陷；发现即修表，不许让工程师"看上下文理解"。

| 编号 | 规则 | 说明与后果 |
| --- | --- | --- |
| N-01 | **状态类词汇禁止与播放控制动词共用汉字。** 状态名不得使用 播放 / 暂停 / 停止 / 循环 等传输控制词；发生冲突时**状态词让位**，改用「暂缓」「挂起」一类专指流程状态的词 | 已发生的实例：`On Hold` 原定"暂停"，与 B-01 `Play / Pause = 播放 / 暂停` 撞词。用户看到状态列写"暂停"会理解成"该镜头正在播放"，真实语义是评审流程挂起。已改「暂缓」 |
| N-02 | **同一英文词在不同语义域可各译一名，但必须在词条备注里互相点名** | 例：`Open` 在评论状态域是"未解决"（E-19），在镜头状态域同译"未解决"以保持同源；若将来出现第三种语义，须新增词条并注明与既有词条的区别 |
| N-03 | **不同英文词不得共用同一中文词**，除非二者在本项目里确实是同一概念 | 例：`Remove` 与 `Delete` 必须"移除/删除"分开（V-02）；`Correction` 统一"修正"，不另造"返修"。**判定细则见下方「同字不同域」三条件**——不看字形，看会不会被并置误读 |
| N-04 | 新增或修改任何词条后，须全文搜该中文词，确认没有第二个语义域在用 | 这是 N-01 能被发现的唯一手段。本次 `On Hold` 撞词逃过了三轮评审，就是因为没人搜"暂停" |

**给评审的一句话**：术语表的错，比工程师抄错更难发现——因为所有人都默认表是对的。凡是"看起来通顺"的词，都要再问一句"这个词在别的面板里是不是另有含义"。

#### N-03 判定细则：「同字不同域」三条件

只按**字形相同**判 N-03 会大量误杀（`关闭` 会同时命中 `Close`、`Mask Off`、`已关闭`），正确判据是「**是否会被并置误读**」。三条**全中才放行，缺一条即改词**：

| 条件 | 判定内容 | 不成立时 |
| --- | --- | --- |
| ① 词法单位不同 | 一个是合成词的谓语成分，一个是独立动作词。例：`遮幅关闭` 的"关闭"是"遮幅处于关闭态"的谓语；`关闭` 按钮的"关闭"是动作本身 | 同形且同为独立动作词 → 必须改词 |
| ② 语境不共屏 | 两处**不会在同一面板/同一次视觉扫描里被并排看到**。例：遮幅是 86 px 工具栏下拉项，`Close` 是对话框底部按钮 | 一旦共屏，本条即不成立 → 必须改词（见下方反例） |
| ③ 无低成本更优替代 | **举证责任在放行方**：主张放行，必须给出"为什么替代词更差"的具体理由，不能只说"我觉得也行" | 举不出 → 视为有更优替代 → 改词 |

**② 是核心条件**：撞词伤人的前提是会被并排看到，不是字形相同。

**已判例（放行）**：`Mask Off = 遮幅关闭`（D-22）vs `Close = 关闭`（I-24）。
举证：①"关闭"在"遮幅关闭"里是谓语成分；②工具栏下拉 vs 对话框按钮，不共屏；③「关闭遮幅」是动词短语，与同下拉里的 `1.85:1` / `2.39:1` 不成对；「无遮幅」语义偏（`Mask Off` 是关闭遮幅这个状态，不是"没有遮幅这个概念"）。三条成立 → 放行。

**反例（放行可撤销）**：若将来 `遮幅关闭` 与 `关闭` 变成**同屏**（例如把遮幅选项挪进一个带"关闭"按钮的对话框），条件② 立即不成立，**必须改词**——改用「无遮幅」或「遮幅：无」，二者都不含"关闭"。
→ **放行是有条件、可撤销的，不是永久豁免。** 一旦布局变更导致共屏，需重新判一次并修表。

**已判例 2（放行）：`shotstrip.py:147` 的 `"Remove selected occurrence from playlist (Delete)"`**
译文：`将所选条目从播放列表移除（Delete）`
不判 N-03 违规，理由：这句话里只有**一个中文动作词**"移除"，`Delete` 是**快捷键键名**，按规则 14 保留英文——二者分属两个层级（动作 vs 键名），不是同一语义域里的两个动词。
**但这条放行是有前提的**：一旦有人把 `(Delete)` 译成「删除」，提示就变成"从播放列表移除（删除）"——同一句里两个中文动作词、语义还互相矛盾（移除不动文件，删除才动文件），那时**必须改回英文键名**，而不是改"移除"。
延伸：`Remove selected clips from Sources and the playlist. Files are not deleted.`（`playlist.py:264`）同理——句中的 `not deleted` 描述的是行为后果，应译「不会删除文件」；它与该句的动作词"移除"不构成撞词，因为一个是动作、一个是后果说明。**判据：同一句里出现两个中文动作词时才需要警惕，一个动作词 + 一个键名/后果说明不算。**

**反向边界（防止把上面这条用过头）**：若将来出现"一个中文动作词 + 一个**中文**键名"（例如有人把 `(Delete)` 写成「（删除键）」），也**不构成撞词**——键名的功能是告诉用户按哪个键，不是描述动作。**判撞词的真正标准是"用户会不会误以为两个动作都作用于文件"，不是数同字。**
但要说清两件事的区别：**"不算撞词"不等于"允许把键名译成中文"**——键名的书写形式归规则 14 管，仍应保留 `Delete`；N-03 只管"是否会误读"，不管"写法对不对"。两条规则各管一段，不要混用。

## 5. 文案风格规则（15 条，全部强制）

1. **省略号**：原文以 `...` 结尾表示会弹出对话框的，中文一律改为单个全角省略号 `…`（`导入素材…`），不得写成 `...`、`。。。` 或 `…...`。不弹窗的项禁止加省略号。
2. **长度**：按钮与菜单项以 2–4 字为宜，最长不超 6 字；宁可"动词 + 名词"（`导出图像序列`），不要整句（`把当前的这些帧都导出成图片序列`）。
3. **状态栏句式**：已完成事件用 `{对象}已{动词}：{值}`，例 `Playlist saved: {path}` → `播放列表已保存：{path}`；进行中用 `正在{动词}…`；失败用 `{对象}失败：{原因}`。
4. **占位符与代码依赖字符原样保留**：`{path}`、`{name}`、`{frame}`、`{count}`、`{total}`、`{fps:g}`、`{0}`、`%d`、`%s`、`\n`、`\t` 的花括号、百分号、格式说明符、转义符一律不译、不改大小写、不增删字符（冒号等全角标点转换除外）。译文语序可调，占位符位置可移，但个数与拼写必须一致。**原文中若含被代码 `split()` / 切片依赖的分隔符**（如代理标签里的半角 ` (`、PDF 分栏的 3 个连续半角空格），同样不得改形——详见第 3.2 节「字面量锁」，那一节优先级高于本节的一般性标点规则。
5. **标点**：中文句用全角 `，。：；？！（）「」`；路径、文件名、快捷键、参数值、单位、格式名保留半角，如 `Ctrl+O`、`/tmp/a.exr`、`2.39:1`、`H.264`。**边界**：同一行存在代码语义的分号/冒号（正则字符集、字符串比较、CSV 分隔、键名）绝不碰，见 L-09。
6. **中英文混排空格**：中文与英文单词/数字之间加一个半角空格（`导出 4 帧 EXR`、`启用 OCIO 色彩管理`）；但倍数 `1x`、百分比 `50%`、时间码 `01:00:00:00`、`2.39:1` 内部与相邻标点不加空格。
7. **状态条结构**：保留 `名词 | 值` 的竖线结构，竖线两侧各一个半角空格；中文不用全大写强调（`SOURCES` → `素材来源`，不是 `素材来源` 加粗或全大写）。
8. **不译清单**：FrameDeck、OCIO、ACES、AOV、EXR、DPX、LUT、Log、Raw、HDR、SMPTE、FPS、RGB、R/G/B/A、Alpha、Luma 的代码值、CSV、PDF、MP4、MOV、MXF、JPEG/JPG、PNG、TIFF、ProRes、H.264、AAC、HUD（仅文档/注释）、A/B 侧代号。**（已定稿，lead 已批准）** CSV 导出表头保持英文小写——常量是 `COLUMNS`（无前缀），9 个键为 `frame, timecode, type, content, color, x, y, done, timestamp`；`.fdplaylist` 与笔记 sidecar 的 JSON 字段名同样不动；`PREFERENCES_SCHEMA`、`restore_last_session`、`setApplicationName` / `setOrganizationName` 也属禁译（改了用户配置全部重置）。这些是接口契约，中文化会破坏 Excel 与下游脚本、并使已保存工程读不回。见验收项 V-01 与字面量锁 L-05。
9. **Gamma 例外**：正文与控件一律"伽马"；当它是色彩空间名/预设名的一部分（`sRGB Gamma`、`Gamma 2.2`）时保留英文 `Gamma`。
10. **错误消息三段式**：`发生了什么。怎么办。（原始信息：{error}）`。系统异常文本、路径、文件名校验原样附在末尾，不译不改写。
11. **标点收尾**：对话框标题为名词短语、不加句号；正文为完整句、句末带全角句号；单行动作按钮不加标点。
12. **量词**：帧 → `帧`，镜头 → `个镜头`，片段 → `个片段`，文件 → `个文件`，路径 → `条路径`；不写 `帧数:3` 这类半角冒号混排。
13. **按钮族**：提问型对话框用 `是 / 否`；执行型对话框用 `确定 / 取消`；破坏性操作按钮写明后果（`清除全部缓存`），不要笼统 `是`。
14. **快捷键要按场景分两种写法**，不可混用：
    - **状态栏/提示条里的并列快捷键串**：写物理键名原样 —— `Space`、`Y`、`E`、`Ctrl`、`F11`、`Alt+Left`。因为同一排里已有 `Y`、`E`、`Ctrl` 这些英文字母键，若只把 Space 换成"空格"，会出现 `空格：播放  |  滚轮：缩放  |  Y：伽马  |  E：曝光` 这种中英参差的排布。例（`__init__.py:771`）：`Space：播放  |  滚轮：缩放  |  Y：伽马  |  E：曝光  |  双击：全屏  |  Ctrl+点击 2 个素材：对比`
    - **正文叙述句里的按键**：写「空格」——因为句子是中文，`按空格播放`、`空格键切换全屏` 读起来自然。例（tooltip）：`播放（空格）`、`按空格播放 / 暂停`。
    - 通用禁止项（两种场景都适用）：禁止译成"控制键 + O"，禁止本地化键名（如"空格条"），禁止把 `Ctrl` 译"控制"。
15. **路径与文件名**：不译、不换行、不加中文引号；正文需引用术语时用「」（如「划像」），不用英文双引号。

## 6. 易错点（最容易被译歪的 10 个词）

| # | 英文 | 错误译法 | 正确译法 | 一句话说明 |
| --- | --- | --- | --- | --- |
| 1 | Wipe | 擦除 / 擦除过渡 / 划动 | 划像 | Wipe 是两条画面之间的扫除式分屏对比；"擦除"对应 Erase/Eraser，是擦掉画面内容，语义正好相反 |
| 2 | Bin | 箱子 / 分箱 / 仓库 | 素材箱 | Premiere 中文版既定译法；"箱"是收纳素材的容器，不是写实木箱 |
| 3 | Shot | 射击 / 拍摄 / 快照 | 镜头 | 视效交付单位；"快照"是 Snapshot，"拍摄"是动作 |
| 4 | Proxy | 代理服务器 / 代理器 | 代理 | 指代理媒体/代理分辨率（降采样预览）；译成服务器会被理解成网络代理 |
| 5 | Plate | 盘子 / 板子 / 底板 | 实拍原素材 | 视效行业指摄影机拍回的原始素材（plate），与"背景板"不是一回事 |
| 6 | Comp | 比较 / 压缩 / 组件 | 合成 | composite 的行业简称；"比较"是 Compare，"压缩"是 Compress，三者不能互换 |
| 7 | Sequence | 序号 / 序列号 | 序列；图像序列 | 时间线语义为"序列"；Image Sequence 必须写"图像序列"限定，单独的"序列"不要裸用 |
| 8 | Correction | 正确 / 纠正 / 校对 | 修正 | 审片意见类别兼镜头状态，统一"修正"；不要因为口语常说"返修"就另造第二套译名 |
| 9 | Open（评论状态） | 打开 / 开启 | 未解决 | 与 Resolved 配对；译"打开"会和"打开文件/打开播放列表"在同一界面里打架 |
| 10 | Scrub / Review / Frame | 擦洗 / 回顾 / 画面 | 拖动预览 / 审片 / 帧 | Scrub 是拖播放头预览；Review 是审片不是回顾；Frame 是帧，画幅对应 Aspect/Format |

补充三点工程侧高频误伤（不算术语，但出错率最高）：
- **`Remove` 与 `Delete` 写反**：播放列表里 `Remove` 只是从列表移除（源文件不动），必须译"移除"；`Delete` 是删除。两者文案必须不同。
- **占位符被吃掉**：`Playlist saved: {path}` 里冒号改全角、前后空格处理时，最容易被连带删掉 `{path}` 外的空格或把 `{` 换成全角，导致 `.format()` 抛异常。改完全量跑一次界面冒烟。
- **把全角标点规则套到代码依赖的字符上**：这是本次最容易造成真实功能损坏的一类。`2K (2048 x 1152)` 的括号一旦改成全角 `（）`，HUD 的 RES 行立刻显示异常（`split(" (")` 找不到分隔）；PDF 分栏的 3 个半角空格被规整成 1 个或换成全角，页码/帧号/时间码会挤成一坨。**凡第 3.2 节列出的字面量，拿不准一律不动。**
